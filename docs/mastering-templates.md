# 마스터링 템플릿 기준값과 근거

작성 2026-10-21. 코드 정본은 `src/lib/mastering/templates.ts`(템플릿 40종), `compose.ts`(용도·장르·느낌 조합, 배경음악 모드), `automaster.ts`(분석 → 체인, 안전장치). 품질 검사는 `templates-quality.test.ts`.

## 1. 처리 순서 — 분석이 먼저, 템플릿은 성격만

`autoMaster(분석, 템플릿)` → `masterToTarget(…)`(렌더해서 재고 다시 맞춤) 순서로 처리한다.

1. **톤 보정(분석 기반)**: 곡의 1/3 옥타브 평균 스펙트럼과 템플릿 톤 목표(`tone`: 1kHz 기준 기울기 dB/oct, 120Hz 아래 덧셈, 8kHz 위 덧셈)의 차이를 EQ 밴드마다 구해 **60%만** 메운다(±4dB).
2. **템플릿 성격(상대값)**: 템플릿 EQ 게인은 보정 위에 더하는 「성격」이다. 곡이 이미 그 방향으로 넘쳐 있으면 넘친 만큼 덜어낸다(`characterShare`). 예: 고역 +2.5 성격인데 곡이 목표보다 3dB 밝으면 성격 몫 0, 보정 -1.8만 남는다. 예전에는 고정 게인 위에 보정을 더해서, 이미 밝은 곡도 템플릿이 고역을 계속 올렸다.
3. **다이내믹**: 크레스트로 압축 강도를 정한다(16dB 넘으면 조금 더, 9dB 아래면 줄이고 멀티밴드 끔). 원본 PLR 대비 결과 PLR 감소가 허용치를 넘을 것 같으면 압축·멀티밴드·클리퍼를 먼저 줄이고, 리미터 몫만으로도 넘으면 목표 음량을 낮춘다. 낮춘 목표는 `targetLufs` 로 돌려준다.
4. **폭**: 좌우 상관 0.6 아래부터 템플릿의 넓히기를 비례해서 줄이고, 0.3 아래면 넓히기 없이 전체 90%. 150Hz 아래 사이드가 -14dB 보다 크면 120Hz 아래를 모노로.
5. **천장·음량**: 리미터 천장 = 템플릿 트루피크 - 0.2dB(측정 여유). 리미터 게인은 목표 LUFS 에 맞게 미리 예측하고, `masterToTarget` 이 실제로 렌더해서 할선법으로 ±0.15 LU 까지 좁힌다.
6. **렌더 안전장치(`masterToTarget`)**: 렌더 결과로 다시 판정한다.
   - PLR 감소가 허용치를 넘으면 압축·새추레이션·트랜지언트·클리퍼를 풀고, 리미터가 실제로 천장을 치고 있을 때만 목표를 낮춘다(리미터가 놀고 있으면 목표를 낮춰도 PLR 이 그대로라서 대신 EQ 보정을 30%씩 덜 쓴다).
   - 트루피크가 천장을 넘으면 리미터 천장을 그만큼 안으로.
   - 리미터만으로 목표에 못 닿으면(조용한 구간이 길고 큰 구간이 짧은 곡: 리미터를 더 밀면 조용한 블록이 게이트 안으로 들어와 통합 음량이 오히려 떨어진다) 컴프가 일부를 맡게 한다. 리미터 게인 상한 24dB 를 넘는 몫은 입력 트림(최대 +12dB)으로.

### PLR 감소 허용치

| 분류 | 허용치 | 해당 |
|---|---|---|
| 배경음악·클래식 계열 | 3 dB | jazz, classical, piano-solo, ambient, drama-bgm, use-bgm, use-broadcast, 배경음악 모드 납품처 |
| 큰 소리(-10 LUFS 이상) 또는 천장 -1 초과 | 9 dB | 클럽·음반·댄스·힙합 계열 |
| 그 밖(스트리밍 등) | 6 dB | 나머지 |

조합(`composeChoice`)은 용도와 장르 중 엄격한 쪽을 쓴다. 단 크게 만드는 용도(클럽·음반)는 용도 값.
결과 PLR 은 「천장 - 목표 LUFS」 를 넘을 수 없으므로, 원본 PLR 이 큰 곡을 큰 목표로 보내면 허용치를 지키려고 목표가 내려갈 수 있다. 품질 검사 표의 「목표 하향」 열이 그 경우다.

### 배경음악 모드 (use-bgm · use-broadcast, compose.ts `applyUse`)

대사와 섞일 전제. 컴프 비율 ≤ 2, 멀티밴드·클리퍼 끔, 리미터 게인 시작값 ≤ +2dB, 대사 대역(2kHz) 중역 -2dB(방송 -1.5dB), 트루피크 -2dBTP, PLR 감소 ≤ 3dB. 이제 장르 없이 용도만 골라도 적용된다(예전에는 장르를 같이 골랐을 때만).

## 3. 템플릿별 기준값

- **톤 기울기**(기울기 dB/oct / 120Hz 아래 / 8kHz 위)와 **EQ 성격**(저/저중/중/중고/고 dB)은 공개 표준이 없는 **경험적 설계값**이다. 핑크 노이즈(-3 dB/oct)보다 조금 가파른 기울기를 출발점으로(템플릿 값은 1kHz 기준 -3.2 ~ -5.2 dB/oct), 장르 특성(808·서브 강조, 보컬 존재감, 로파이의 깎인 고역 등)을 더해 정했다. 실측 레퍼런스 곡 대조로 검증한 값이 아니다.
- 압축 비율·어택·릴리스·폭·새추레이션도 경험적 설계값이다. 자동 마스터링이 곡 분석으로 다시 조정한다(1절).
- 음량·천장은 2절 근거. 장르 템플릿의 음량은 그 장르 상업 음원이 흔히 도달하는 크기의 경험값이다.

## 4. 품질 검사

`npx vitest run src/lib/mastering/templates-quality.test.ts`

- 샘플: `MASTERING_SAMPLES` 폴더(`node scripts/mastering/fetch-library-samples.mjs <폴더> 5` 가 대표 보관함에서 장르가 다른 곡을 골라 48kHz float WAV 로 저장, 읽기 전용). 폴더가 없거나 `MASTERING_SAMPLES=none` 이면 합성 신호 3종(밝은/어두운/다이내믹 큰)으로 대신하고 테스트 이름에 「합성」 이라고 적는다. 실제 곡이 있어도 안전장치 점검용 「합성-다이내믹」 을 늘 함께 돌린다.
- 각 곡은 가장 큰 5초 구간(3분 제한 때문).
- 축: 템플릿 40 / 스타일 카드 8 × 캐릭터 4(그대로·깨끗하게·따뜻하게·펀치감) / 납품처 8(destinations.ts) × 캐릭터 4.
- 판정: 통합 LUFS = 실제 목표 ±0.5, 트루피크 ≤ 천장, 샘플 클리핑 0(샘플 피크 ≤ 트루피크 < 0), PLR 감소 ≤ 허용치. 목표를 낮춘 경우는 「목표 하향」 열에 따로 적는다.
- `MASTERING_QUALITY_OUT=<파일>` 을 주면 곡 × 항목 전체 표를 그 파일로 쓴다.
- 합성 신호는 20Hz 하이패스를 먼저 건다. 핑크 노이즈 생성기가 실제 곡에 없는 초저역을 품어서, 체인의 25Hz 하이패스가 피크를 2~3dB 깎은 것이 「PLR 감소」 로 잘못 잡혔기 때문이다.
