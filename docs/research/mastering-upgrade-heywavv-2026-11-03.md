## 1. heywavv 가 하는 것 (확인한 것만)

### 1.1 화면·흐름
- 첫 화면에서 WAV 곡 또는 스템 ZIP 을 올린다. 첫 곡은 가입 없이 들어볼 수 있다. 작업 흐름은 안내 문구 기준으로 분석(스펙트럼·다이내믹·이미징) → 판단(곡마다 문제 찾기) → 필요한 만큼만 적용이다.
- 랜딩에 원본 ↔ 처리본 토글 샘플이 있다(AI 곡 쇳소리 제거 시각화, 재즈·힙합·EDM 3종). 결과 화면(로그인 뒤)은 보지 못했다. 「분석 리포트」「실시간 프리뷰」가 있다고만 적혀 있다.
- 무료 도구 「믹스 체크」(/check): 음량·트루피크·다이내믹·저역·스테레오·밸런스 6가지를 브라우저 안에서 30초에 재고, 파일은 서버로 안 올라간다. 가입 전 입구 역할이다.
- 업데이트 로그(10/19 정식 오픈): 10/20 AI 곡 아티팩트 정리 강도 「자연스럽게 / 강하게」, 10/21 여러 곡 선택 삭제·순차 다운로드, 10/22 마지막 음량 「여유롭게(약 -12) / 기본 / 강하게(약 -9)」.
- 업로드 시 「AI로 만든 곡인가요?」를 먼저 묻는다.

## 2. 기능별 비교표

판정 기준: 있음 / 없음 / 더 나음(우리가 앞섬) / 열세(heywavv 가 앞섬). heywavv 쪽은 공개 페이지·영상에서 확인한 범위만. 결과 화면 내부는 미확인이라 「미확인」으로 표시했다.

|---|---|---|---|
| 곡 분석 후 곡마다 다른 처리 | 있음 (적응형) | 있음 (`analyze` → `automaster`, 톤 60% 보정·압축·폭·천장 곡별 조정, 근거 `docs/mastering-templates.md`) | 동등 |
| AI 생성곡 고역 쇳소리 정리 | 있음 (전용 단계, 자연스럽게/강하게) | 부분 (EQ 의 「거친 고역 다듬기」는 3.5kHz·10kHz 고정 EQ, `dsp.ts`. 곡을 보고 켜지 않음. 5~9kHz 과다는 디에서만 켬) | 열세 |

## 3. 업그레이드 제안 (우선순위)

화면 문구는 한국어, 타사 상표 사용 안 함(「AI로 만든 곡」으로 표기). 모든 제안은 브라우저 처리라 유료 API 가 필요 없다.

| 순위 | 제안 | 비용 | 난이도 | 사용자 가치 |
|---|---|---|---|---|
| 1 | AI 곡 고음 정리 전용 단계 | 0원(브라우저) | 중상 | 최상 |
| 2 | 내보내기 전 자동 검수 + 결과 요약 카드 | 0원 | 중 | 상 |
| 3 | 「발매 점검」 단독 도구(업로드 없는 6항목 측정) | 0원 | 하 | 상 (유입 입구) |
| 4 | 간단 마스터링 결과 화면 개선 | 0원 | 하 | 중상 |
| 5 | 스템 충돌 분석과 EQ 제안 | 0원 | 상 | 중 |

### 1순위. AI 곡 고음 정리 전용 단계
- 무엇: 처리 체인 맨 앞에 「AI 곡 고음 정리」를 넣는다. 곡을 분석해 8~16kHz 대의 지글거림(대역 에너지가 짧은 시간에 불규칙하게 튀는 정도, 고역 평탄도)을 재고, 튈 때만 그 대역을 줄이는 동적 처리(기존 `dyneq` 구조 확장 또는 고역 전용 대역 컴프)로 한다. 정적 EQ(`deharsh`)와 달리 평소 공기감은 유지한다. 강도는 「자연스럽게 / 강하게」 2단.
- 화면: 곡 올릴 때 또는 간단 마스터링 첫 단계에서 「AI로 만든 곡이에요?」를 묻고, 곡 보관함에서 온 곡이면 자동으로 켜 둔다(우리는 곡 출처를 이미 안다. 경쟁사는 사용자에게 묻는다). 결과에 「줄인 고음: 최대 -N dB」 표시.
- 왜 1순위: 우리 사용자는 거의 AI 생성곡이고, 마스터링으로 음량을 올리면 쇳소리가 같이 커진다. 경쟁사가 영상·랜딩에서 가장 크게 내세우는 차별점이 이것이다.
- 위험: 효과를 말이 아닌 숫자와 귀로 확인해야 한다. 완료 기준을 「쇳소리 지표(고역 불규칙 에너지)가 처리 전후 N% 이상 감소 + 5~9kHz 평균 레벨 변화 1dB 이내」처럼 측정 가능하게 정하고, 실제 AI 생성곡 5곡 이상으로 전후 스펙트로그램 대조 후 판단한다. 지표 임계값은 아직 정하지 않았으니 구현 전에 샘플로 정한다.

### 2순위. 내보내기 전 자동 검수 + 결과 요약 카드
- 무엇: 현재 `masterToTarget` 의 렌더 후 재측정을 확장한다. 검사 항목: 클리핑 샘플 수(`clipSamples`), 트루피크 초과, PLR 감소 허용치, 좌우 상관도(모노 호환), 저역 과다, 고역 급증. 이상이면 설정을 조정해 재처리하고(최대 2~3회), 끝내 안 되면 「이 설정으로는 안전하게 내보낼 수 없어요. 강도를 낮춰 볼까요?」 안내와 함께 한 단계 약한 결과로 대체한다.
- 화면: 완료 후 한 장짜리 카드에 처리 전후 6지표(음량·트루피크·다이내믹·저역·스테레오·밸런스)를 나란히, 문제 없으면 초록 「발매 점검 통과」. 지금도 재측정 리포트(`Panels.tsx`)는 있으나 전문 설정 안에 묻혀 있다. 간단 마스터링 결과 화면으로 끌어낸다.
- 왜: 사용자가 「잘 됐다」를 믿는 장치다. 우리 엔진은 이미 측정을 다 한다. 표시와 재시도 규칙만 더하면 된다.
- 위험: 재처리 루프가 무한 반복하지 않게 횟수 상한, 결과가 원본보다 나빠지는 경우(검사 통과해도 원본이 더 나음) 원본 유지 선택지.

### 3순위. 「발매 점검」 단독 도구
- 무엇: 곡 ⋯ 메뉴와 쿠키뮤직 첫 화면에 「발매 점검」 입구를 만든다. 곡을 끌어다 놓으면 브라우저 안에서만 6항목(음량·트루피크·다이내믹·저역·스테레오·밸런스)을 재고 「발매해도 되는지」를 신호등으로 알려 주고, 문제가 있으면 「간단 마스터링으로 고치기」로 이어 준다. 업로드 없음.
- 왜: 이미 `analyzeAudio` 가 있어 신규 DSP 가 없다. 로그인 없이 쓸 수 있는 공개 페이지로 두면 검색 유입과 가입 전 체험 입구가 된다(경쟁사가 같은 구조로 운영 중).
- 위험: 화면 문구에서 기준값 근거를 과장하지 않는다(`docs/mastering-destinations.md` 의 확인/참고/미확인 등급을 따른다).

### 4순위. 간단 마스터링 결과 화면 개선
- 무엇: (a) 음량 선택 문구를 「여유롭게 / 기본 / 강하게」로 통일하고 각각의 대략적인 LUFS 를 작게 병기, (b) 스트리밍·쇼츠 등 용도를 한 줄 선택으로 노출(납품처 표 재사용), (c) 결과 직후 「원본 ↔ 마스터」 즉시 비교(음량 맞춤 기본 켜짐)를 같은 대화창 안에서 제공, (d) 「고급 마스터링으로 이어서 다듬기」 버튼에 현재 설정을 넘겨 준다(이미 `onAdvanced` 가 있으니 설정 전달만 확인).
- 비용·저장: 지금 보관함에는 MP3 320 만 저장하고 WAV 는 내려받기 전용이다. WAV 를 보관함에 저장하면 저장소(무료 한도) 부담이 커지므로 이 제안에서는 바꾸지 않는다. 필요하면 별도 결정.
- 왜: 선택 단계를 줄이고 결과를 바로 검증하게 하는 마감. 구현량이 적다.

### 5순위. 스템 충돌 분석과 EQ 제안
- 무엇: 스템을 올리면 스템끼리 대역이 겹치는 곳(예: 베이스와 킥 60~120Hz, 보컬과 기타 1~4kHz)을 대역별 에너지 겹침으로 찾아 「베이스를 100Hz 에서 -2dB 깎아 보세요」처럼 믹서에 제안 버튼으로 보여 준다.
- 왜: 경쟁사의 스템 마스터링이 내세우는 부분. 우리 믹서는 수동이라 초보에게 어렵다.
- 위험: 스템이 있는 사용자가 소수다. 곡→스템 자동 분리는 현재 유료 기능(2트랙)이고, 브라우저 안에서 0원으로 분리하는 방법(모델을 내려받아 WebGPU/WASM 으로 처리)은 모델 크기·속도·품질을 검증하지 못했다. 이번 제안에는 넣지 않고 별도 연구 후보로 남긴다.

### 후순위·보류
- 프리셋 학습(내 곡 취향 저장·재사용): 레퍼런스 매칭과 프리셋 저장이 이미 있어 수요 확인 뒤에.
- 앨범 일관 마스터: 우리는 이미 앨범 패널에 있음. 곡 간 톤 편차까지 맞추는 확장은 경쟁사도 「준비중」이라 급하지 않다.
- 마케팅 문구: 「엔지니어 vs 자동 블라인드 테스트」 같은 비교는 우리 쪽 측정 근거를 쌓은 뒤에. 지금 근거(템플릿 EQ·압축 값)는 「경험적 설계값」으로 문서에 적혀 있다(`docs/mastering-templates.md` 3절).

## 4. 확인하지 못한 것 (판단 보류)
- heywavv 로그인 뒤 결과 화면(분석 리포트의 실제 구성, 프리뷰, 다운로드 흐름)과 STUDIO 가격. 가입·결제를 하지 않는 조건이라 열지 않았다.
- 실제 처리 품질(귀 비교). 영상의 블라인드 테스트는 제작사 자체 시연이라 객관 근거로 쓰지 않는다. 필요하면 별도로 같은 곡 2개로 비교 청취를 한다.
- 「자체 개발 알고리즘」의 구체 방식. 영상에서 말한 「문제 고음이 올라올 때만 선택적 억제」가 동적 대역 처리임은 추정이다(설명 그대로의 해석이며 내부 구현은 공개되지 않음).
- 우리 쪽 AI 곡 고음 정리의 효과. 구현 후 실제 곡으로 전후 측정이 필요하다.
