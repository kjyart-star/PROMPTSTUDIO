# AI 곡 고음 정리 · 자동 검수 · 발매 점검 (2026-11-03)

근거: `docs/research/mastering-upgrade-heywavv-2026-11-03.md` 상위 제안 1~4. 전부 브라우저 처리, 비용 0원.

## 1. AI 곡 고음 정리 (체인 맨 앞 `aiclean`)
- 코드: `src/lib/mastering/dsp.ts` `AiCleanStage`, 측정 `src/lib/mastering/aiclean.ts`.
- 방식: 3~12kHz 를 반 옥타브 5대역(3.2·4.35·5.93·8.07·11kHz, 감지용 이웃 2.35·15kHz)으로 나눈다. 대역 에너지(8ms)의 dB 에서 양옆 대역 평균을 뺀 「스펙트럼 모양」을 재고, 그 모양이 느린 기준(1.5초)보다 튄 만큼(모양 방향 스펙트럴 플럭스)이 기준을 넘을 때만 그 대역을 벨 EQ(Q 3)로 줄인다. 하이햇·심벌·후렴처럼 고역 전체가 같이 오르면 모양이 그대로라 줄이지 않는다.
- 강도: 자연스럽게(기준 1.5dB, 비율 4, 최대 6dB) / 강하게(기준 0.5dB, 비율 10, 최대 10dB).
- 켜는 규칙: 곡 보관함 곡(우리가 만든 AI 곡)이면 자동으로 켠다(간단 마스터링 기본 「자연스럽게」, 고급 마스터링은 곡을 열 때). 직접 올린 파일은 꺼져 있고 체인에서 켤 수 있다. 저장해 둔 옛 체인(14칸)은 순서를 지키고 맨 앞에 이 칸만 끼운다.
- 결과 표시: 「줄인 고음: 최대 -N dB (튀는 순간에만)」.

### 실제 곡 측정 (공개 곡 12곡, 48kHz, 무음 처리)
측정: `AICLEAN_EVAL_DIR=<폴더> FFMPEG=<ffmpeg> npx vitest run src/lib/mastering/aiclean.eval.test.ts` — 고음 정리만 켠 체인. 전체 표 `docs/research/aiclean-eval-2026-11-03/report.md`, 전후 스펙트로그램(위부터 원본·자연스럽게·강하게, 2~14kHz) 같은 폴더 `*.compare.jpg`.

| 모드 | 고역 피크 에너지 감소(상위 1%) | 고역 평균 손실(평균 / 최대) | 쇳소리 지표(고역 돌출 피크) | 스펙트럼 평탄도 | 최대 감쇠 |
|---|---|---|---|---|---|
| 자연스럽게 | -0.42 dB | 0.35 / 0.55 dB | -0.71 dB (-6.5%) | +0.0035 | -5.1 dB |
| 강하게 | -1.03 dB | 0.93 / 1.20 dB | -1.12 dB (-10.4%) | +0.0080 | -7.0 dB |

- 음색이 둔해지지 않는지(고역 평균 손실 1.5dB 이하): 12곡 모두 통과(최대 1.20dB).
- 한계: 효과는 「튀는 순간만 몇 dB」 수준이라 평균 지표 변화는 작다. 강하게는 고역 피크 감소와 평균 손실이 비슷해, 쇳소리가 심한 곡에만 권한다. 측정 지표(반 옥타브 고정 대역)는 처리 대역과 따로 정했다.
- 쇳소리 지표 정의: 프레임(2048, 절반 겹침)마다 대역 dB − 양옆 평균을 구하고, 그 대역의 곡 전체 중앙값을 뺀 값의 최댓값 → 곡 전체 상위 1%.

## 2. 내보내기 전 자동 검수 · 결과 카드
- 코드: `src/lib/mastering/releaseCheck.ts` (`releaseCheck`, `autoFix`), `actions.ts` `renderChecked`.
- 렌더한 파일을 다시 풀어 6항목(음량 목표 편차·트루피크·클리핑·강약 PLR·모노 호환 상관도·고음 거칠기)을 잰다. 문제(빨강)나 피크·클리핑 주의가 있으면 설정을 고쳐(천장 낮춤·목표 낮춤·폭 줄임·고음 정리 켬/강하게) 한 번만 다시 만든다. 다시 만든 쪽이 더 나쁘면 처음 것을 쓴다. 남은 문제는 카드에 원인·해결 방법으로 보여 준다.
- 적용: 간단 마스터링(보관함 저장 전), 고급 마스터링 「파일로 받기」·「함께 받기」.
- 판정 기준: 음량 ±1 통과·±2 주의, 트루피크 목표 이하 통과·0 이하 주의, 클리핑 0 통과·10 이하 주의, PLR 7 이상 통과·5 이상 주의, 상관도 0.3 이상 통과·0 이상 주의, 고역 돌출 12.5dB 이하 통과·15 이하 주의(공개 AI 곡 12곡 측정 8.8~12.8dB 로 잡은 앱 기준).

## 3. 발매 점검 단독 도구
- 진입: 스튜디오 마스터링 탭 메뉴 줄 「발매 점검」. 보관함 곡 또는 내 컴퓨터 파일 → 브라우저 안에서만 분석(업로드 없음) → 6항목 신호등 → 「이 곡 마스터링하기」.
- 공개 입구 페이지(설계만, 구현 안 함):
  - 주소 `/music/check`(로그인 불필요). 파일 끌어 놓기 하나, 같은 `ReleaseCheckCard`.
  - 분석은 지금 코드 그대로(`decodeAudio` + `analyzeAudio({ harsh: true })` 워커). 서버 경로·저장 없음 → 비용 0원.
  - 결과 아래 「간단 마스터링으로 고치기」 → 로그인 뒤 스튜디오 마스터링 탭으로(파일은 브라우저 메모리로 넘김, 업로드 없음).
  - 기준값 문구는 `docs/mastering-destinations.md` 의 확인/참고 등급을 따르고, 고음 거칠기는 「앱 참고 기준」이라고 적는다.
  - 검색 유입용 설명 문단·FAQ 는 결과물이 쌓인 뒤 붙인다(템플릿 랜딩과 같은 시점).

## 4. 간단 마스터링 마감
- 음량 3단 「조용하게(약 -14) · 보통(약 -12) · 크게(약 -9)」, 용도 한 줄 선택(음원 스트리밍·동영상·짧은 영상·영상 배경음악·클럽·CD) — 용도를 고르면 어울리는 음량이 먼저 골라진다. 최대 피크·사운드 성향 선택은 그대로.
- 결과 직후: 점검 카드, 원곡↔마스터링 전후 비교 재생(음량 맞춤 기본 켜짐, 큰 쪽만 줄임), WAV 내려받기(보관함에는 MP3 320 만 저장하는 규칙 유지).
- 「고급 마스터링에서 이어서」: 결과 체인·목표·고음 정리 설정을 그대로 넘긴다(`mastering/handoff.ts`).
- 이전 4단(-14/-12/-10/-8)은 3단으로 바뀌었다. -8·-10 같은 다른 값은 고급 마스터링에서 그대로 고를 수 있다.

## 5. 메인 스레드 밖 처리
- `src/lib/mastering/worker/` — 렌더·분석·트루피크/음량 측정·WAV 만들기를 Web Worker 에서 한다. 원본 PCM 은 1M 샘플 조각으로 한 번만 보내 두고 다시 쓴다(최근 2개). 워커를 못 쓰면 그 자리 처리로 넘어간다(`offthread.ts`).
- 실시간 재생은 기존 AudioWorklet(`public/mastering/master-chain-worklet.js`, `dsp.ts` 에서 생성).
- 로컬 확인(2분 26초 곡, 1280×860): 발매 점검 분석·곡 열기·자동 맞춤·3곳 WAV 내보내기 동안 50ms 넘는 메인 스레드 작업 0건(PerformanceObserver longtask).
